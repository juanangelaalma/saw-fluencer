# Plan: Auth System Epic 1

**ID**: 20260607001
**Status**: ready
**Created**: 2026-06-07
**Author**: @architect

---

## TL;DR

Modify Laravel Breeze auth to match PRD Epic 1. System will use username/password auth, role-based Admin/Manajer access, temporary lockout, inactive-user enforcement, and Admin-only user management.

---

## Context

### Background

PRD `docs/prds/functionality.md` requires authorized Admin/Manajer access and Admin-controlled user accounts.

### Current State

- Laravel 13 Breeze Blade app.
- Login uses `email` + `password`.
- No role, username, active status, or user management.
- Public register/password reset/email verification/profile email flows exist.

### Target State

- Login uses `username` + `password`.
- Roles stored as `admin` and `manajer`.
- Admin and Manajer redirect to separate placeholder dashboards.
- Public register/reset/email verification removed.
- Admin manages users; Manajer denied with 403 after user-management routes exist.
- Inactive users cannot login and active inactive sessions are forced logout.
- Initial Admin seeded from `.env`.

---

## Objectives

### Primary Goals

1. Implement US-01 login/logout requirements.
2. Implement US-02 Admin user management requirements.
3. Remove email-dependent Breeze flows for username-only auth.
4. Add tests for auth, roles, inactive users, lockout, and user management access.

### Success Criteria

- [ ] Login form shows Username and Password.
- [ ] Correct credentials redirect Admin to Admin dashboard and Manajer to Manajer dashboard.
- [ ] Wrong credentials show `Username atau password salah`.
- [ ] Five failed attempts lock same lowercase username + IP for 10 minutes.
- [ ] Logout clears session.
- [ ] Admin can create, edit, and deactivate users.
- [ ] Admin cannot change own role or deactivate self.
- [ ] Manajer cannot access user management routes; direct access returns 403 after `admin.users.*` routes exist.
- [ ] Passwords require minimum 8 characters.
- [ ] Public register/reset/email verification/profile email routes removed or inaccessible.

### Non-Goals

- Full SAW features from Epic 2-5.
- Full dashboard content beyond placeholders.
- Public password recovery. Password recovery is Admin-managed.
- Production-safe data preservation. App is pre-production; DB refresh acceptable.

### TODO 1.2: Refactor auth routes/request/controller and inactive/admin middleware

**Agent**: @laravel
**Dispatch**: single
**Estimated Time**: 60m
**Dependencies**: 1.1

#### Objective

Replace email login with username login, disable public email-dependent auth flows, add role/inactive enforcement.

#### Acceptance Criteria

- [ ] Login request validates `username` and `password`.
- [ ] Auth attempt uses normalized lowercase username + password.
- [ ] Failed credential message is `Username atau password salah`.
- [ ] Inactive user login returns same generic message.
- [ ] RateLimiter uses lowercase username + IP, max 5 attempts, decay 600 seconds.
- [ ] Successful Admin login redirects to admin dashboard.
- [ ] Successful Manajer login redirects to manager dashboard.
- [ ] Logout invalidates session and regenerates token.
- [ ] Public register, password reset, and email verification routes disabled/removed.
- [ ] Old `/dashboard` no longer requires `verified`; redirects to role dashboard or resolves by role.
- [ ] Middleware forces inactive authenticated users to logout and redirect login.
- [ ] Admin-only middleware/gate is registered for later `admin.users.*` route protection.

#### Implementation Notes

- Keep CSRF on all form routes.
- Prefer dedicated middleware like `EnsureUserIsActive` and `EnsureUserIsAdmin` if Laravel 13 app structure supports route aliases in bootstrap config.
- If middleware files not present, create under expected Laravel app middleware location and register per framework conventions.

#### QA Scenarios

| Scenario | Input | Expected Output | Verification |
|---|---|---|---|
| Admin login | valid admin username/password | redirect admin dashboard | Feature test |
| Manajer login | valid manajer username/password | redirect manager dashboard | Feature test |
| Wrong login | bad password | message `Username atau password salah` | Feature test |
| Lockout | 5 failed attempts | blocked 10 minutes | Feature test with time travel |
| Inactive session | active session user made inactive | logout + login redirect | Feature test |
| Admin middleware probe | non-admin hits admin-protected route after routes exist | 403 | Covered in Task 2.2 feature test |

#### Files to Modify

- `routes/auth.php` - remove register/reset/verification routes; keep login/logout.
- `routes/web.php` - role dashboards, `/dashboard` role redirect, auth/inactive middleware usage only. Task 2.2 owns `admin.users.*` routes.
- `app/Http/Controllers/Auth/AuthenticatedSessionController.php` - role redirect.
- `app/Http/Requests/Auth/LoginRequest.php` - username auth/rate limit/errors/inactive check.
- `app/Http/Middleware/EnsureUserIsActive.php` - force logout inactive users.
- `app/Http/Middleware/EnsureUserIsAdmin.php` - Admin-only route access.
- `bootstrap/app.php` - middleware aliases if needed.

### TODO 2.2: Build Admin user management controller/routes/views

**Agent**: @laravel
**Dispatch**: single
**Estimated Time**: 90m
**Dependencies**: 2.1

#### Objective

Create Admin-only user management with create/edit/deactivate behavior from PRD.

#### Acceptance Criteria

- [ ] Admin can view user list with name, username, role, active status, actions.
- [ ] Admin can create user with Nama, Username, Password, Role.
- [ ] Username validation: required string max 50 alpha_dash unique.
- [ ] Password validation: required min 8 on create.
- [ ] Role selection required and restricted to `admin`/`manajer`.
- [ ] Admin can edit name, username, role, active status/password rules as allowed.

- [ ] Admin cannot deactivate self.

- Use resource-like routes except destroy performs deactivate or use named deactivate route.

- Preserve active/inactive users visible in list.

## Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Removing email breaks Breeze references | High | High | Full grep update routes/views/tests/factory/model |
| Admin lockout/no-admin state | Medium | High | Env-seeded admin, self role/deactivate blocks |
| User enumeration via inactive errors | Medium | Medium | Same generic login error for invalid/inactive |
| RateLimiter not persistent account lock | Medium | Low | Disclose; username+IP lock meets Epic 1 for now |
| Manajer access through direct URL | Medium | High | Server-side middleware returns 403 |

## Assumptions

- App is pre-production; DB refresh/migration rewrite acceptable.
- Temporary lockout uses Laravel RateLimiter, not `locked_until` column.
- Admin can edit own name/password but cannot change own role or deactivate self.
- Password recovery is Admin-managed through user management.
- Role display labels are localized in UI; stored role values stay `admin`/`manajer`.
